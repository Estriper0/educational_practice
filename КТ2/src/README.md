# Контроль приёмки партии кабеля
Автор: Косточко Сергей Алексеевич, ИКБО-10-24.

Python 3.12.14; совместимость: Python 3.12+. Внешних зависимостей нет.
Из каталога src выполнить:

```console
python main.py example.json --batch B1
python check_scenarios.py
```

Входной файл example.json содержит все девять сущностей логической модели.
Два образца, две обязательные проверки, четыре измерения. Пределы 0–10 Ohm
и 100–1000 MOhm — демонстрационные, не нормативные значения для реального кабеля.
Одна запись batches означает одну попытку приёмки; повторная проверка оформляется
новой записью с новым идентификатором, старые результаты сохраняются.

Ожидаемый вывод:
```json
{"batch_id":"B1","proposal":"accepted","issues":[],"status":"awaiting_approval","approval":null}
```
Форматирование вывода может отличаться. Программа выдаёт проект решения.
Для фиксации утверждения добавьте в protocols запись:
```json
{"id":"PR1","batch_id":"B1","employee_id":"E2","decision":"accepted","approved_at":"2026-11-03T12:00:00+03:00"}
```
Тогда status будет accepted. Решение не создаётся автоматически.
Значение 20 у M1 даёт proposal rejected; удаление M1 — incomplete.
Пустой перечень образцов или правил не допускает положительного решения.
Повтор одной пары sample_id/requirement_id означает незавершённый контроль;
неверные ключи, ссылки, NaN и бесконечность завершают программу с кодом 2.

Операции: validate_measurements — проверить формат результатов; evaluate —
сопоставить результаты с планом; make_protocol — сформировать проект протокола.
Алгоритм A имеет O(r) времени, B — O(n*m*(r+1)); поиск измерений намеренно
выполняется последовательным просмотром для прозрачной оценки худшего случая.
Справочные проверки целостности validate_data выполняются до алгоритма B.
Состояние хранится в JSON, база данных и HTTP-сервис на этом этапе не требуются.
