# Испытания партии кабеля — Java

Нужен JDK 17 или новее, сборка обычным `javac`, внешних библиотек нет.
Проверено JDK 24.0.2 с `--release 17` 24.11.2026.

Откройте терминал **в этой папке** (`src/java` после распаковки).
Команды PowerShell:

```powershell
New-Item -ItemType Directory -Force build | Out-Null
javac --release 17 -encoding UTF-8 -d build *.java
java -cp build Main example.json --batch B1
java -cp build Verification example.json
```

Linux/macOS: вместо первой команды используйте `mkdir -p build`, остальные те же.
Если команды не найдены, добавьте папку `bin` установленного JDK в PATH.

Ожидаемый JSON для неизменённого `example.json`:

```json
{"batch_id":"B1","proposal":"accepted","issues":[],"status":"awaiting_approval","approval":null}
```

Исходный JSON совпадает с `КТ2/src/example.json` в репозитории.
Сравнение с процедурной версией из корня репозитория:

```powershell
python КТ2/src/main.py КТ2/src/example.json --batch B1
```

Сравниваются значения JSON, порядок элементов `issues` сохраняется; пробелы и
переносы вывода несущественны. `proposal` — проект решения; до появления
достоверной записи в `protocols` статус остаётся `awaiting_approval`.
Программа ничего не записывает во входной файл. При некорректном входе
выходной код 2, сообщение идёт в stderr. Тексты ошибок на языках различаются.

`Verification` выполняет 18 сценариев, в том числе включённость границ,
NaN, логическое значение вместо числа, дубликат измерения, нарушенную ссылку,
отсутствие образцов, чужие полномочия и противоречивое утверждение.
Ожидаемая последняя строка: `OK: 18 scenarios`. Ошибка завершает проверку
ненулевым кодом; ключ `-ea` не требуется.

Дополнительная проверка в репозитории: `materials/kt3/verify_equivalence.py`
сравнивает все поля результата Java и Python на 56 вариантах входа.
Путь к JDK и папке сборки задаётся в начале этого служебного скрипта.
Процедурная программа повторно в архив не включена согласно памятке.

Девять сущностей модели представлены классами Product, Plan, Requirement,
PlanRequirement, Batch, Sample, Measurement, Employee, Protocol. Approver
наследует Employee и переопределяет canApprove. Check реализован в FormatCheck
и LimitCheck. Dataset валидирует JSON и создаёт неизменяемые коллекции
объектов, ProtocolService выполняет сопоставление и формирует проект протокола.
Алгоритмы A и B сохранены: O(r) и O(n*m*r).
Предполагаются строковые идентификаторы и строковые описательные поля, как в
данных КТ2; произвольная смена типов полей не входит в контракт.

`Json.java` написан для этого проекта; чужой код из архива напарника не включён.
Минимальный кодек читает стандартный JSON. Нестандартные токены NaN/Infinity
в файле отклоняются; проверка NaN в Verification проверяет объектную границу.
